Drill-Down Tables in Tableau

An operating rollup you can expand and collapse row by row, like folders in a file explorer, built with two parameters, a handful of calculated fields and one click action. No extensions, no data reloads.

The big idea

Tableau has no built-in "expand this row" for a table that spans several hierarchy levels at once. You can rebuild it with three ideas:

  1. Every row has an address, like a folder path. A region's address is |Company|G1|D1|R1|. A child's address always starts with its parent's address.
  2. One parameter is the memory. p_OpenedRows holds the address of every opened row, each wrapped in ~.
  3. One yes/no test per row decides whether it shows. That test is the only filter on the table.

Think of the Explorer panel in VS Code or Windows: a folder's contents only appear when you open that folder and every folder above it.

Click a row with ▸ to open it, or ▾ to close it.

This runs the workbook's formulas, word for word, in your browser on the same fictional data. Open a few rows, then tick Show hidden rows and why to see the rule that decides each one.

The three rules

Rule 1 · ⬆ The selected unit and everything above it always show.
Rule 2 · ⬇ Rows directly under the selected unit always show.
Rule 3 · 📂 A deeper row shows only when every row between it and the selected unit is opened. One closed row in between hides it.

Rows in a different branch (neither above nor below the selected unit) never show.

The building blocks

Two parameters and six calculated fields. The data needs one row per unit with its level and its parents' numbers. The rollup values are already computed for every unit, so nothing is aggregated on the fly.

p_SelectedUnitparameterWhere the tree starts. Default Company.
p_OpenedRowsparameterThe memory: every opened row's address, wrapped in ~. Default ~ (nothing open).

dd_SelectedLevelcalcThe selected unit's level: the number of | in its address, minus 1.

dd_ClickResultcalc, per rowWhat p_OpenedRows becomes if you click this row.

The address and the comparisons

// dd_Path
'|Company|'
 + IIF([Level] >= 2, [Group No] + '|', '')
 + IIF([Level] >= 3, [Division No] + '|', '')
 + IIF([Level] >= 4, [Region No] + '|', '')
 + IIF([Level] >= 5, [Store No] + '|', '')

// lod_SelectedPath
{ FIXED : MAX(IF [Unit No] = [p_SelectedUnit] THEN [dd_Path] END) }

// dd_SelectedLevel
LEN([lod_SelectedPath]) - LEN(REPLACE([lod_SelectedPath], '|', '')) - 1

// flg_IsSelectedOrAbove
STARTSWITH([lod_SelectedPath], [dd_Path])

// flg_IsBelowSelected
STARTSWITH([dd_Path], [lod_SelectedPath]) AND [dd_Path] <> [lod_SelectedPath]

The filter: three rules in one test

// dd_ShowRow  (filter the table to True)
[flg_IsSelectedOrAbove]                                   // rule 1
OR ( [flg_IsBelowSelected]
 AND ([dd_SelectedLevel] >= 2 OR [Level] <= 2
      OR CONTAINS([p_OpenedRows], '~|Company|' + [Group No] + '|~'))
 AND ([dd_SelectedLevel] >= 3 OR [Level] <= 3
      OR CONTAINS([p_OpenedRows], '~|Company|' + [Group No] + '|' + [Division No] + '|~'))
 AND ([dd_SelectedLevel] >= 4 OR [Level] <= 4
      OR CONTAINS([p_OpenedRows], '~|Company|' + [Group No] + '|' + [Division No] + '|' + [Region No] + '|~')) )

Each AND line checks one parent (group, division, region). A parent is fine when it is the selected unit or above it, when the row is too shallow to have that parent, or when the parent is opened. Direct children are too shallow to fail any line, which is rule 2.

The click

A parameter action can only copy a value from the clicked row. It can't add to or remove from a list. So every row works out in advance what the memory should become if it is clicked:

// dd_ClickResult
IF [flg_IsBelowSelected] AND [Level] < 5 THEN
  IF CONTAINS([p_OpenedRows], '~' + [dd_Path] + '~')
  THEN REGEXP_REPLACE([p_OpenedRows],
         '~' + REPLACE([dd_Path], '|', '\|') + '[^~]*', '')   // close it and everything under it
  ELSE [p_OpenedRows] + [dd_Path] + '~'                       // open it
  END
ELSE [p_OpenedRows] END

Closing removes the row's address and every address that starts with it, because the pattern matches the longer addresses too. That is why closing a group also closes its divisions and regions. The | has to be escaped because it means "or" in a regular expression.

The action itself: Dashboard › Actions › Add Action › Change Parameter, run on Select, source sheet = the table, source field = dd_ClickResult, target = p_OpenedRows, and on clearing the selection, keep the current value. Put dd_ClickResult on the table's Detail shelf so the action can read it.

Build it yourself

  1. Shape the data: one row per unit with Unit No, Unit Name, Level (1–5), the parent numbers, a Sort order (parent before children) and the metric values.
  2. Create the two parameters (strings). Make p_SelectedUnit a list of the units at levels 1–4.
  3. Create the six calculated fields above.
  4. Build the table: Sort (hidden header) and a label field on Rows, the metrics on Columns, dd_ShowRow on Filters set to True.
  5. Add the label: indent by level and add ▸ / ▾ from a flg_IsOpen test (CONTAINS(p_OpenedRows, '~' + dd_Path + '~')).
  6. Put dd_ClickResult on Detail and add the Change Parameter action.
  7. Add a "Start over" button: a one-mark sheet whose two parameter actions write ~ into p_OpenedRows and Company into p_SelectedUnit.

The "How the Drill Works" dashboard

The workbook has a second dashboard that teaches the logic inside Tableau. It shows the drill-down, every parameter and calculation with its current value, and a table of every row with the rule that shows or hides it. Click around and watch the values change.

Gotchas

Wrap addresses in ~

Without a delimiter on both sides, |Company|G1| would match inside |Company|G1|D1| and G1 inside G12. Testing for ~address~ only matches whole entries.

Don't put dimensions on the Tooltip shelf

A row-level text field on Tooltip turns the pill red and blanks the whole sheet. Put it on Detail and reference it from the tooltip text instead.

Selection clears itself

After a click the row's label changes (▸ becomes ▾), so Tableau sees a new mark and drops the selection. You can click the same row again straight away, with no deselect action needed.

Pre-compute the rollups

Each unit's values come from the data, not from aggregating the visible rows. That keeps every row correct whatever is open, and the table never re-queries when you drill.
